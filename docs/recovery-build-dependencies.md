# Recovered source dependencies

The original repository commit `35d7902` referenced source types absent from its source tree while retaining compiled assemblies and portable PDBs. These dependencies were reconstructed during the September 16 recovery from those assemblies using ILSpy. They preserve recovered behavior; they are not verbatim original source. The evidence-bound workflow commit `822ec63` depended on that local recovery, so a separate dependency commit captures the source required for a reproducible checkout.

The dependency closure includes extraction/retrieval contracts, notification contracts, the image service, SEO contracts/registration, and the SlateKit project and Web references/services/assets. It removes the obsolete AutoMapper 12 DI extension beside AutoMapper 16. It also restores the fixed empty-SQLite baseline, initialization wiring and foreign-key-correct workflow-family seeding required by API startup and regression tests. Approval fixtures now seed and assert IdeaRecord approval and persisted article workflow runs rather than obsolete ContentIdea status behavior.

The SQL baseline represents the recovered September 16 EF model, not the exact historical migration schema. Only migration `20260419003557_SplitIdeaArticleWorkflowPipelines` is recorded; future migrations run normally. Initialization is transactional and restricted to empty SQLite databases. Existing databases retain their existing migration path. Tests cover schema creation, reinitialization, user-table preservation and rollback. The baseline must not be regenerated for later model changes.

This dependency capture does not configure or test live integrations. QMD needs the external command. SEO providers have no connected measurements; GoogleTrendsProvider now returns unknowns rather than estimated measurements. The recovered image service retains prompt/error logging and placeholder fallback behavior. The recovered workflow hub has no authorization attribute. These are recovery limitations, not features validated for public deployment. No live AI/image/search/QMD calls or existing database changes are part of dependency verification.

The repository historically tracks bin/obj output. Verification uses a local detached sparse checkout excluding those tracked outputs, regenerates restore/build assets from the existing NuGet cache with package sources cleared, and runs the four offline test suites. Generated outputs, private runtime artifacts, unrelated package upgrades and the earlier local recovery report are excluded from this commit. No deployment or workflow activation is implied by successful compilation and tests.
