# Evidence-bound workflow repairs

This change records repairs to the existing personal publishing workflow. It builds on the locally recovered source tree; untouched source-recovery files, project recovery changes and tracked generated artifacts are deliberately outside this commit scope. Validation of the recovered worktree is not proof that a clean checkout builds without those recovery dependencies.

## Research and article safeguards

Collected URLs and cleaned excerpts survive ideation, approval snapshots and the research-to-brief handoff. Keyword questions retain their intent-bearing words. Unsupported source selection, synthetic fallback prose and report-only editing cannot satisfy article delivery. Blocking QA findings prevent workflow completion.

Full specification imports remain draft-only and preserve historical versions and logical source identifiers. Each actual workflow step records its input/output identity and acceptance evidence. Explicit failed-step retries preserve completed work; unsupported policies or capabilities block production activation. Scoped article authorization is required; implementing the path does not automatically activate it.

Source-bound briefs select real source IDs and exact excerpt quotes. Post-edit checks preserve numbers, headings, evidence and structural content, followed by fresh source review. Final delivery verifies actual assets, inline source links, clickable contents, exact HTML/Markdown hashes and required gates. Native hypothetical evidence disclosures retain a complete static Markdown equivalent. Automated provenance checks and model editorial judgments do not independently establish truth or real reader engagement.

The generic manual brief recovery service validates a stopped, failed run, frozen identities, preserved response hashes and a separately approved recovery packet. Recovery is atomic, retains the original failure and attempt count, and consumes the preserved response without another brief model call. Adding this service is not approval to execute recovery on any existing run.

## Reviewed idea ranking

`idea-independent-ranking-v2` is explicitly opt-in. Its scoring stage makes a fresh critical review call with generator scores withheld. Reasons and exact source quotes are checked before accepting the review. The same configured model/provider may serve both roles; this is separate model review, not independent human review.

Proposed configurable default weights:

| Dimension | Weight |
|---|---:|
| Reader problem | 10% |
| Audience fit | 15% |
| Usefulness | 15% |
| Reader engagement potential | 10% |
| Differentiation | 10% |
| SEO intent fit | 10% |
| SEO demand | 15% |
| SEO competition opportunity | 10% |
| SEO trend | 5% |

These provisional defaults total 60% editorial value and 40% SEO opportunity; they are not finalized user choices or empirically calibrated outcome probabilities. Reasons use explicit 0–4 anchors, without artificial score caps. Engagement concerns relatable openings, useful examples and progression rather than rewarding decorative interactions.

No verified market measurement provider is configured for this contract. Demand, competition and trend remain null; ordinary search snippets cannot substitute measured metrics. Evidence-backed intent fit contributes to provisional ranking. Unknown components retain their possible contribution to a score range rather than being replaced with zero or renormalized away. Overall score remains null while components are unknown. For example, 3/4 on assessable dimensions gives 52.5–82.5 with 70% assessed. This is an arithmetic range, not a statistical confidence interval.

Queue ordering uses the evidenced lower bound provisionally; overlapping ranges do not establish a winner. Historical scores keep their original values/scales and are displayed separately. The queue exposes actual weights, reasons, source quotes and limitations. Invalid or missing assessments cannot substitute generator scores. Legacy numeric compatibility fields are explicitly distinguished from the nullable reviewed overall score.

## Validation and execution limits

Offline tests cover the historical failure classes, source cleaning, keyword continuity, actual workflow execution, gate enforcement, quote provenance, retries, atomic recovery, score arithmetic, missing/invalid evidence, reviewer separation, provisional ordering and unchanged historical scores. Actual local browser checks use synthetic records and a separate database with zero workflow runs; screenshots/runtime logs remain outside the repository.

No activation, live AI call, credentials, application data mutation, article publication or external push is performed by committing these changes. Reviewed sample contracts in test fixtures remain inactive. Live provider behavior, real reader engagement and measured SEO opportunity require separate bounded verification and an explicit provider/data decision.
